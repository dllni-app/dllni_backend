## Explicitly missing, but unsafe to cherry-pick

- **V2 visit-scoped execution:** current `SupervisorScheduledV2Controller::unsupportedTransition` and `RejectUnsupportedV2SupervisorExecution` deliberately refuse booking-wide start/verification/finish/attendance changes on V2. Old branch **does not implement** per-room/per-period attendance, start, completion, handover or immutable supervisor transfer and cannot fill that gap.
- **Signed extension pricing and settlement:** old booking-wide `cleaning_supervisor_extensions` approval is a different ledger from shared `CleaningTimeWarning` / `CleaningOpenTimeExtension` flows. It lacks approved frozen participant prices, worker/supervisor schedule conflicts, payable/commission reconciliation and verified exactly-once billing for V2. Never enable by copying it.
- **Legacy-only extras:** old media deletion, operational replacement acknowledgment and objection-resolution routes are not independently safe or an approved V2 delta until audit/custody, media-retention and customer-consent contracts are frozen. They should be designed against the current service/schema rather than ported wholesale.

## Safe integrated change and validation scope

The only safe delta from this review is **test coverage and this audit document**. `tests/Feature/Cleaning/SupervisorStaleBranchIntegrationSafetyTest.php` freezes canonical supervisor route/auth/hold middleware, incompatible migration-column evidence and a SQLite-backed negative booking-wide V2 transition. It does not register endpoints, change schema, bypass release HOLD, alter signed prices or create new money/stock transitions.

**Release status remains HOLD.** Independent security review, clean/upgrade MySQL migration evidence, visit execution acceptance, shared extension/financial and custody reconciliation, authenticated browser/mobile flow and required online Android builds remain separate sign-off gates under the main plan. This branch is an isolated review candidate; do not merge or push until the prime's gate decision.
